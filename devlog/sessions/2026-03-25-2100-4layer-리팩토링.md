## 4-Layer 아키텍처 설계

### 계층 구조

```
┌─────────────────────────────────────┐
│  crawlers/  (28 sources)            │  데이터 수집
│  - API crawlers (3)                 │
│  - Playwright crawlers (25)         │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  analyzer/                          │  AI 필터링
│  - Claude domain scoring (6)       │
│  - Keyword boosting                 │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  notifiers/                         │  알림 전송
│  - Telegram (domain tags)           │
│  - n8n webhook                      │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  knowledge/                         │  데이터 저장
│  - SQLite DB                        │
│  - Notice deduplication             │
└─────────────────────────────────────┘
```

### 설계 원칙

1. **단일 책임 원칙 (SRP)**: 각 계층은 하나의 역할만 담당
2. **확장성**: 새 크롤러/알림 채널 추가 용이
3. **장애 격리**: API 크롤러 실패 시 전체 시스템 영향 최소화
4. **테스트 용이성**: 계층별 독립 테스트 가능

모든 신규 크롤러는 Playwright 기반이며 다음 구조를 따릅니다.

```python
class BaseNoticeCrawler:
    """공통 베이스 크롤러"""

    async def crawl(self) -> List[Notice]:
        async with async_playwright() as p:
            browser = await p.chromium.launch()
            page = await browser.new_page()

            try:
                return await self._extract_notices(page)
            except Exception as e:
                logger.error(f"Crawl failed: {e}")
                return []
            finally:
                await browser.close()

    @abstractmethod
    async def _extract_notices(self, page) -> List[Notice]:
        pass
```

### 스코어링 알고리즘

```python
async def score_notice(notice: Notice) -> Dict[str, int]:
    """각 도메인별 관련도 스코어 (0-100)"""

    scores = {}
    for domain_id, domain_info in domains.items():
        # 1. Claude 기본 스코어 (0-100)
        base_score = await claude_score(notice, domain_info)

        # 2. 키워드 부스팅 (+20)
        if has_boost_keyword(notice, domain_info["boost_keywords"]):
            base_score = min(100, base_score + 20)

        # 3. 도메인 가중치 적용
        final_score = int(base_score * domain_info["weight"])

        scores[domain_id] = final_score

    return scores
```

```python
def should_filter_landscape(notice: Notice) -> bool:
    """G2B 소스이고 조경 키워드 포함 시 필터링"""

    if notice.source != "g2b":
        return False

    # 관련도 60 이상만 필터링 (오탐 방지)
    landscape_score = calculate_landscape_score(notice)
    if landscape_score < 60:
        return False

    # 조경 키워드 체크
    landscape_keywords = config.filters.g2b_landscape.keywords
    return any(kw in notice.title for kw in landscape_keywords)
```

## graceful degradation 구현

### 문제 상황

기존에는 subsidy24 API 장애 시 전체 크롤링이 중단되었습니다.

```python
# Before (장애 시 전체 중단)
results = []
for crawler in crawlers:
    results.extend(await crawler.crawl())  # 하나 실패 시 전체 중단
```

### 해결책

각 크롤러를 독립적으로 실행하고 실패를 로깅합니다.

```python
# After (graceful degradation)
results = []
for crawler in crawlers:
    try:
        crawler_results = await crawler.crawl()
        results.extend(crawler_results)
        logger.info(f"{crawler.name}: {len(crawler_results)} notices")
    except Exception as e:
        logger.error(f"{crawler.name} failed: {e}", exc_info=True)
        # 다음 크롤러 계속 실행
        continue

# 최소 1개 크롤러라도 성공하면 파이프라인 지속
if results:
    await analyzer.process(results)
```

### 효과

- API 크롤러 장애 시에도 Playwright 크롤러는 정상 동작
- 시스템 가용성 향상
- 장애 영향 범위 최소화
